## 追加（22:00 之后）：用户实测报障 → 第 3 层解封并全绿

### 用户报的错
```
ir_patch  失败 · schema
[schema] ir_patch: arguments do not match the tool schema:
    missing required property 'base_version'; missing required property 'ops'
```

### 根因（C-49）
`tcad/llm/client.py:OpenAIClient._parse`：
```python
except json.JSONDecodeError:
    args = {}          # 截断被吞掉
```
模型正在写一个很大的 `ir_patch`（手机支架侧轮廓 + 约束 + 需求），**JSON 被每步 token 上限截断** →
客户端把 `JSONDecodeError` 换成 `{}` → 下游 schema 检查如实报告"缺这两个必填键" —— **而模型其实正写到一半**。
它最合理的反应就是把同样大的 patch 再发一次，撞同一堵墙。

**真机复现**：`max_tokens=1200` 时 `finish_reason="length"`，`arguments` 是 1359 字符非法 JSON，结尾停在 `"direction": [0.0`。
`LlmReply.finish_reason` 当场就有，**没有任何人读它**。

### 修法
1. `ToolCall` 新增 `args_error`（解析失败原因）+ `args_raw_len`；`args == {}` 保留（活下来是对的，但"为什么"必须跟着活下来）。
2. 空字符串**不算错**（无必填参数的工具合法取 `{}`）；合法 JSON 但非对象单独记（同样不是"缺键"）。
3. `engine._step` 派发**之前**短路：不进 hook、不进 handler，按**原因**给处方
   （`finish_reason=="length"` → "撞上每步 token 上限，**把 patch 拆小**"；否则 → "重发合法 JSON"）。
4. 旧测试只断言 `args == {}`——把"静默"固定成了期望行为，已补成也断言原因被记下。

### 真机验证
- **自然跑通**：用户设置（4096）+"创建一个手机支架：楔形主体，前部有个托住手机的挡边" → `succeeded`，5 步，Gate 通过，产出 FCStd/step/stl/manifest。
- **强制截断**（1200）→ 8 步 `succeeded`：`ir_patch`(FAIL，「not usable … character 2017 of 2021」) → OK（照提示改小）→ FAIL（这次真少写 base_version）→ OK×3 → `ir_commit` OK。
