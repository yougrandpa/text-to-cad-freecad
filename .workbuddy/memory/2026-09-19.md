### 本轮揪出的 8 个缺陷（前 5 个是本轮引入或暴露，任何单测都不会发现）
1. `rpc.py` 用了未导入的 `E_COMPILE` —— `detail.get("kind") or E_COMPILE` 短路求值，只在"错误详情没有 kind"时爆。**把精确的 solver 错误替换成 NameError**，恰好摧毁可自修复性。
2. `sqlite_path` 硬编码 `./data/tcad.sqlite3` —— 覆盖 `data_dir` 后库仍指向旧目录，两套配置共用一个库。有三处调用方在手工同步它（正是缺陷的证据）。→ 改为空默认 + `sqlite_file()`。
3. `/settings/llm` 从 Config 反推 provider（Config 无 provider 概念）→ 显示 vllm 而实际用 custom。
4. `base_version: "current"` 被拒 —— 最自然的写法换来无用的 pydantic 错误。→ 纳入工具契约。
5. `build_client` 接受空 `base_url` → **SDK 静默回退 `api.openai.com`**，提示词与 Key 发给了没选的厂商。→ 显式拒绝。
6. UI `$("viewPort")` vs HTML `viewport` → 静默 null。→ 加 id/class/资源引用的静态一致性测试。
7. `SessionDB` 硬绑单线程 → HTTP 线程池下第二个请求即崩。→ `check_same_thread` 参数 + RLock。
8. `context_window` 有默认值 → 无法区分"未设置"与"显式设成 128000"，预算阈值按错窗口标定。→ 改 Optional + `resolved_context_window()`。

**教训**：1/3/4/8 是"默认值或兜底逻辑让错误看起来像正常"；2/5/6/7 是"两个地方各写一遍同一个事实"。前者靠端到端跑出来，后者靠单一事实来源。

## 追加：「跑完了不知道完成」的根因（用户实测反馈）

用户配好 DeepSeek 后实测报："左边模型执行代码，中间不实时渲染，跑完也不知道完成了。" 查出**三个独立缺口**，前两个都是我的错：

### 1. 结论表用枚举名做键，永远匹配不到（直接原因）
`result.state` 从 SSE 来的是 pydantic 对 `(str, Enum)` 的序列化结果 —— **小写值** `"succeeded"`；而我的表键是 `SUCCEEDED`。**永远命中不了**，于是 turn 结束时屏幕上**根本没有结论**，唯一的信号是文字安静地停了。

更糟的是**测试放过了它**：旧测试只断言文件里出现过 "SUCCEEDED"/"EXHAUSTED" 这两个**字符串** —— 它们确实出现过，作为那些永远匹配不到的键。

→ 修：键改小写值；**新测试把表的键与 `TurnState` 本身对比**，两侧再也不可能漂移。同类检查适用于 `CheckStatus`/`Severity`（它们恰好是对的）。

### 2. 视图只在 turn 结束后刷新
engine 的 observer 早就在 tool 帧里带了 `images`，但前端**完全没读**。而且 `/render` 只在 handleResult 里调一次。

→ 修：tool 帧带图就立即显示（`applyToolImages` → `displayImage`），Gate 通过的 commit 也刷新视图（模型不主动看图时也有图）。为此服务端必须给图附**可访问的 URL**（engine 报的是磁盘绝对路径，浏览器用不了）。

**证据（帧时序）**：
```
13.6s  ir_commit  ok=True  gate=PASS
13.6s  geo_view   ok=True  images=['iso','top'] urls=[...?version=4]
13.6s  result     state=succeeded
```
两者都排在 `result` 之前 → 确实是过程中更新。

### 3. 进行中没有任何指示
一分钟的静止画面与"卡死"无法区分。→ 加 live 行：当前步骤 + 当前工具 + **已用时秒表**，并**钉在底部**（append 已有节点会移动它 —— 第一版就是被它描述的内容顶上去的）。

### 附带修掉的真 bug
**未知模型返回 500 而非 404**。根因值得记：
```python
def current_version(self, model_id):
    try: return int(self.ir_store.load(model_id).version)
    except FileNotFoundError: return 0     # ← "不存在" 与 "就是 v0" 同值
```
`create()` 造出来的模型**就是 v0**，所以它区分不了。render/artifacts 三个端点改为一律用 `load()` 取版本，并在该方法 docstring 里写明这个歧义。**症状出现在 UI（中间显示 Internal Server Error），根因在存储层的返回值语义。**

## 追加：「配置不保存」其实是我的操作造成的

用户报：每次配完 API Key 重启服务就要重配，且回到默认模型。

**实测结论：配置从来没丢。** `data/settings.json` 存在（0600），serve 启动日志明确打印
`model -> DeepSeek / deepseek-v4-flash @ https://api.deepseek.com/v1`，UI 的 chip 与设置面板也都正确。

**真实原因**：我为了验证实时渲染，用**同一个 8765 端口** + `--data-dir .tcad_live2` + 指向离线替身起了服务。用户在那段时间打开界面，看到 `自定义 (OpenAI 兼容) / stub-scripted`，且那个数据目录里没有他的 key —— 于是完全合理地判断为「配置没保存 + 回到默认模型」。

**代码侧的修复**（问题是真的，只是不在持久化逻辑里）：**界面从不说明它连的是哪个实例**。
- `/health` 增加 `data_dir`（从 config 取，未构建服务栈时也能答）
- 设置对话框**顶部**显示：数据目录 / settings.json 路径 / **是否真的写到了磁盘**（`✓ 已持久化，重启后仍生效` vs `⚠ 尚未写入磁盘`）
- 顶栏 chip 的 tooltip 带上数据目录
- Key 输入框的 placeholder 改为 `已保存 sk-…0280 —— 留空表示不修改`（输入框永远不回显明文，空着本是正常状态，但读起来像"没保存"）

**教训（已写入 MEMORY.md 操作纪律）**：验证/演示不要占用用户正在用的端口；用户报「功能没用」时，先确认他连的是哪个实例/数据目录。

## 追加：真机首跑 DeepSeek —— 第 2 步就炸，暴露一个协议缺口

用户配好 key 后第一次真机跑（需求：「给这个立方体加两个手臂和两条腿」），第 2 步报：

```
400 The `reasoning_content` in the thinking mode must be passed back to the API.
```

**根因**：DeepSeek 思考模式返回的 assistant 消息带 `reasoning_content`，**同一轮内**多步循环回放时必须原样带回。而它**在进入系统的第一跳就丢了** —— `LlmReply` 没这个字段，`_parse` 也没读，engine 自然无从回显。

**一轮是多步循环 ⇒ 每步都在回放上一步的 assistant 消息 ⇒ 这个缺陷必然在第 2 步爆，且任何思考模型都会。**

**为什么 402 个离线测试全绿也没发现**：`stub_llm.py` 不产生 reasoning（它不是思考模型），这条要求只存在于真实协议里。与"只测成功路径"是同一类盲区——**只有真机能证明真机**。

**修复**（`client.py` + `engine.py`）：`_parse` 读 `reasoning_content`（回退 `reasoning`）；engine 构造 assistant 消息时**有则回显、无则不加键**（不给普通模型塞 `reasoning_content: null`）。

**修复后真机验证**（「60x40 底板厚 10mm」）：
```
 1.5s ir_get/ir_digest ok   6.1s ir_patch FAIL(invalid IR)   8.7s ir_patch ok
10.2s ir_patch ok          11.2s ir_commit gate=PASS
11.2s RESULT succeeded steps=5 tokens_in=21741 tokens_out=2568
```
**11 秒、5 步、Gate 全绿、几何正确**（60×40×10）。而且第 2 步的失败被**模型自己读懂并修正**（它自己指出 `refs` 的语义）——这是本项目最核心假设（反馈质量决定能否自修复）的第一次真机证据。

**新增** `tests/unit/test_llm_client.py`（这个模块此前一个测试都没有）。
