## 已核实的 FreeCAD API 硬事实（务必记住，避免踩坑）
- ⚠️ **`TopoShape` 没有 `BoundBox` 属性** —— 必须用 `optimalBoundingBox()`（pyi:1189）。写成 `shape.BoundBox` 会 AttributeError。
- ⚠️ **`shape.check()` 的 .pyi 声明 `-> bool`，实现却是成功返回 `None`、失败抛 `ValueError`**（`TopoShapePyImp.cpp:709-725`）—— 必须 try/except，不能写 `if shape.check():`。
- ⚠️ **`SketchObject.solve()` 返回的是 `SolveStatus` 整数（0/1/2/3），不是 DOF**；DOF 必须读 `sketch.DoF`（只读 int 属性）。`FullyConstrained` 也是只读属性。
- ⚠️ **无头环境出不了 PNG**：FreeCAD 全部光栅渲染在 `src/Gui`（`View3DPy.cpp:1006` saveImage；`renderToImage` 明确要求真实 QOpenGLWidget 上下文）。`Mod/Part/App` 与 `Mod/Sketcher/App` 无任何渲染符号。→ 架构改为「worker 回传 `tessellate()` 网格 + supervisor 用 numpy 软件光栅化」。
- `TopoShape.tessellate()` **无容差参数**，签名恒为 `() -> (List[Vector], List)`；网格过大时可改用 `MeshPart.meshFromShape`（App 目录无条件构建，无头可用）。
- `OriginFeatures` 顺序权威定义在 `src/App/Datums.cpp:265-275`：`[0]X轴 [1]Y轴 [2]Z轴 [3]XY面 [4]XZ面 [5]YZ面 [6]原点`。
- 附着真实写法（已核实于测试套件）：`sk.AttachmentSupport = (doc.XY_Plane, [""])` / `(pad, ["Face5"])` / `(body.Origin.OriginFeatures[4], [""])`，配 `sk.MapMode = "FlatFace"`。
- 建模惯用法（对齐 FreeCAD 自身测试 `TestPad.py:42-76`）：`doc.addObject("PartDesign::Body","Body")` → `doc.addObject("Sketcher::SketchObject",...)` → `body.addObject(sk)` → `doc.addObject("PartDesign::Pad","Pad")` + `Pad.Profile = sk` → `body.addObject(pad)` → `doc.recompute()`。**不用 `body.newObject()`**（两种都存在，但设计统一用 addObject）。
- Sketch 构建：`sk.addGeometry(Part.LineSegment(App.Vector(...), App.Vector(...)))` + `sk.addConstraint(Sketcher.Constraint("Coincident", 0, 2, 1, 1))` + `sk.setDatum(idx, value)`；约束类型串权威表在 `Sketcher/App/Constraint.h:190-212`。
- 版本：FreeCAD **26.3.0dev**；构建走 pixi（`pixi run configure && pixi run build` → `build/debug/bin/FreeCADCmd`）。**仓库目前只有源码，尚未构建 —— 这是设计的最大硬前置，未验证。**
- Worker 启动：`FreeCADCmd -c --console -P <path> <bootstrap.py>`；CLI 选项在 `src/App/Application.cpp:2429-2460`，位置参数经 `processFiles()`→`runFile()` 执行（`:3092`/`:3119`）。
- **未核实清单**（首次实现必须用运行时 introspection 核对）：Hole / 模式类特征（LinearPattern 等）/ Fillet / Chamfer / Draft / Thickness 的具体属性名。`Part.checkGeometry`、`Part.checkSolid`、TopoShape 的 `isSolid`/`isCompound`/`Vertices`（本树是 `Vertexes`）、`PartDesign::Pad` 的 `"Dimension"` 枚举值 —— 均确认**不存在**。

## 编译完成后的实测复核（推翻设计文档两条 API 结论）

- ✅ 链路打通：`doc.XY_Plane` 附着 → 草图 → 11 条约束 → solve=0 / DoF=0 / FullyConstrained=True → Pad → **Solid / 6 面 / Volume 24000.0（=60×40×10）/ isValid=True** → STEP 6874B → **往返体积相对误差 = 0.0** → STL 3052B。
- ⚠️ **推翻①**：`TopoShape.BoundBox` **是存在的**（XMin/XMax/XLength/YLength/ZLength 全可用）。设计文档原写「没有 BoundBox 属性，必须用 optimalBoundingBox()」是**错的**。取舍：轴对齐规格校验用 `BoundBox`，`optimalBoundingBox()` 是可旋转 OBB，拿去比轴对齐规格会偏小。
- ⚠️ **推翻②**：`TopoShape.tessellate()` **必须传 tolerance**，`shape.tessellate(0.5)` 才工作；`.pyi` 的无参签名是错的。好处是**网格密度可控**（60×40×10 的 Pad → 8 顶点/12 面片），原先的 IPC 传输体积担忧大幅缓解。
- ⚠️ **新坑**：`FreeCAD.App` **不存在**，`from FreeCAD import App` 抛 ImportError；正确写法 `App = FreeCAD`（与 `Mod/PartDesign/TestPartDesignGui.py:113` 一致）。
- ⚠️ **新坑（误导性错误信息）**：`sketch.setDatum(idx, v)` 在**约束冲突/求解失败**时也抛 `ValueError: Invalid constraint index: N`（`SketchObjectPyImp.cpp:915-920` 把 SolverError 一并映射成这句）。实测踩到：把 DistanceX 加在已用 `Coincident(0,1,-1,1)` 绑到原点的点上 → 冲突。**正确顺序：先绑原点，再标注自由端点。**
- ✅ `shape.check()` 实测返回 `None`（确认设计文档结论）。
- ✅ 全部特征属性名已实测取得（解决原遗留问题 #10）：Hole 53 项、LinearPattern 32、CircularPattern 20、Fillet 19、Chamfer 23、Revolution 35、Groove 34、Mirrored 16。注意命名陷阱：`Suppressed`（非 suppress）、`Originals`（模式类的被阵列对象）。**CircularPattern 没有 Angle/Mode/Reversed**——极坐标阵列优先用 `PolarPattern`。

### 装配层 `tcad/core/wiring.py`（本轮最大价值）
并行开发的队友各自把子系统写成了**自洽的库**，而 loop/tools 是按 `tcad/tools/base.py` 里的窄 Protocol 写的——两种形状对不上，而唯一的缝合处是 `LoopEngine.build_default_services` 里一个**导入路径全是编造的占位实现**（`tcad.worker.handle`、`ContextService`、`Renderer` 都不存在），一调用就 ImportError；因为没人调用所以一直没暴露。现在 `wiring.py` 是唯一的缝合点：
- `SyncWorkerClient`：async `WorkerHandle.request` → **同步 ok/error 信封**（commit.py 与 geo_tools.py 都是 `services.worker.request(...)` 同步调用并读 `res["ok"]`）
- `StoreAdapter`：`IrStore` + `validate_ir` + `ArtifactStore` → Store Protocol（IrStore 没有 `validate_*`/`persist_digest`）
- `RendererAdapter` / `ContextServiceAdapter`：把 `render_views()` / `render_digest_text()` 包装成 Protocol 对象
- `build_context_loader`：Gate 的**只读磁盘**载入器；缺 digest 时降级为「无法证明」而不是抛异常弄死整个 Turn
- `build_hooks`：通过 dispatcher 的 registry 注入内置守卫的依赖，配置保持声明式
- `build_services(cfg)`：真正的入口

### 本轮修掉的真缺陷
1. **写方与读方文件名不一致**：`ArtifactStore.write_digest` 写 `model.json`（它自己的 docstring 却写 `digest.json`），而 `verify/context.py` 读 `digest.json` → 生产环境 Gate **永远读不到磁盘上的 digest**。之所以没炸，是因为我新写的回退路径意外读对了另一个文件名。已统一为 `digest.json`。
2. **审批流是死结**：engine 的 ASK 分支挂起 Turn 却**不创建任何审批记录**，而特权三重门去查一个从未被创建的审批 → 永远无法放行。已补 `_request_approval`（按参数哈希 scoped），并把 approval_id 回传给模型与客户端。
3. `build_default_services` 占位实现 → 改为指向 `build_services` 并给出可操作的报错。

### 服务端 `tcad/server/*`
- **设计要点**：`run_turn` 只在结束时返回一个结果，没有天然流。与其另造一套事件系统，**服务端 tap 了 hook dispatcher**——engine 本来就分发的 `pre_step`/`pre_tool_use`/`pre_commit`/`on_gate_result` 直接变成 SSE 帧。生命周期钩子兼作可观测面。tap **只观察、不改判定**。
- `app.py`：`/health`、`POST /models`、`GET /models/{id}/ir`、`/artifacts`、`POST /chat`(SSE)、`GET /approvals`、`POST /approvals/{id}`。services 可注入，测试无需 FreeCAD。
- `cli.py`：`new` / `chat` / `repl` / `approvals` / `approve`，进程内跑，不需要 uvicorn。
- CLI 真机冒烟通过：`new` 落盘 IR+事件流；`chat` 流式输出真实 hook 事件；**没有 LLM 时优雅报 `FAILED` 并给出清晰错误，不崩**。

## 第三轮：「操作者即 LLM」——我亲自用它完成了建模
用户指令：「继续 直到你自己使用这个功能可以完成建模，你自己就是 llm 不需要其他 llm 了」。
这是一个**方法论上正确**的要求：不接任何模型供应商，由我本人充当 LLM，通过**真实工具面**（真注册表 + 真 ToolContext + 真 hook 检查）逐步建模。它验证的是 harness 与模型的**契约**（工具面是否可猜、失败是否可行动、Gate 是否是唯一裁判），而不是某个模型的智力。

### 交付物
- `tools/agent_driver.py`：驱动器。`--list-tools [--full] [--only X]` 看模型可见的工具面与完整 schema；`--calls FILE` 执行一串工具调用（一个 Turn）；`--worker-probe` 直接问 worker 要 compile/introspect/export/tessellate 的原始结果；`--show-ir` / `--digest`。

- `docs/renders/bracket_{iso,top}.png` + `bracket.step`：最终零件。

### 建模结果（4 步，Gate 由红转绿）
目标：**安装底板 80×50×8，中间 40×20 通槽**，尺寸写成机器可校验需求。
1. 底板草图 + Pad 8mm → ✗ `mass_spec` 体积 32000≠25600（**Gate 精确抓到缺槽**，且 bbox/round_trip/草图全约束都过 → 底板几何正确）
2. 加槽草图 + Pocket → ✗ **全部 SKIP**（约束冲突被静默吞掉）
3. 重建槽草图（草图原点 + `offset` 定位）→ ✗ 体积仍 32000（**Pocket 切了个空**）
4. `update_feature ft_slot {"reversed": true}` → **✓ GATE PASSED**：体积 25600 精确命中、STEP 往返误差 0.0、10 面 24 边

### 挖出 5 个新缺陷（237 个已有测试一个都没抓到）
1. **worker 信封把内层失败压平成成功**（最致命）：`rpc.dispatch` 把「handler 没抛异常」当成调用成功，而返回体里 `ok=false`（约束冲突/无实体可导出/无网格）被外层 `ok=true` 掩盖 → **编译失败被当成编译成功**。已修：`dispatch` 在 `result["ok"] is False` 时构造错误信封，新增 `_first_error()` 统一三种内层错误形状。
2. **`commit.py` 吞掉上游失败**：导出/摘要 `except: pass`，编译的内层 ok 也不检查。已修：收集 `pipeline_notes` 附在 Gate 报告后；导出格式改从 config 读。
3. **Pocket 方向静默无效**：草图在 XY（法向 +Z），`PartDesign::Pocket` **默认朝轮廓法向反方向切（-Z）**，而底板在 +Z 侧 → 切进空气，特征什么都不做**且报告成功**（`ok=true`、`errors=[]`、体积不变，`shape_type` 从 Solid 变 Compound）。修法：`"reversed": true`，**并把这条写进 `ir_patch` 的工具描述**（模型可见契约）。
4. **草图过约束的定位方式**：把一条线的**起点与终点**都用绝对坐标标注 + H/V 约束 → 求解器冲突。正确做法：**轮廓建在草图自己的原点上**（绑一条线到草图原点 + 标注对侧端点），再用 `offset` 整体定位。已写进工具描述。
5. **工具面对模型不可用**：`ir_patch` 的 `required` 只列 `base_version`（pydantic 因 `ops` 有默认值就不标 required），且 `payload` 是**完全无类型的 object** —— 唯一真正干活的工具，参数是黑箱。已修：`_ir_patch_schema()` 钉死 `required: [base_version, ops]`；`_IR_PATCH_DESCRIPTION` 逐 op 给出 payload 形状 + 约束 refs 语义 + 两条陷阱。

### 方法论结论（重要，值得沿用）
- **「操作者即 LLM」是缺失的那一层验证**。单元测试证明各层自洽；端到端测试证明装配可用；但**只有亲自当一回模型**，才知道工具面是否可猜、失败信息是否足以自修复。
- **「诊断质量」与「诊断可达性」是两件事**。worker 的 solver 错误一直写得很好（带 `feature_id`、带具体约束与数值），但被缺陷 2/1 两层掩盖。后者更容易漏、也更致命。
- **静默无效比报错危险**。缺陷 3 表现为"成功"。后续可考虑在编译期做**特征贡献校验**（V 层已用体积/拓扑事后抓住）。
- 修完两个协议/管线缺陷后重跑第 2 步场景：`ir_commit` 会返回 `[tool error: solver] ... (feature_id=sk_slot)`，模型拿到的是「你的槽草图约束冲突」——这才是能自修复的反馈。
