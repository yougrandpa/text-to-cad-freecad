# 手摇削铅笔工具盒：Agent 实测与优化

> 历史归档：包含已被后续实现替代的描述。现行说明见 [文档索引](../../docs/README.md)；测试及验收结论仅适用于原记录。

本轮让一个子代理充当建模 AI，通过真实工具注册表和 FreeCAD 创建模型。
不调用外部模型 API，也不以任意 FreeCAD Python 绕过声明式 IR。

## 实测反馈与修复

| 实测障碍 | 修复 |
| --- | --- |
| 没有创建独立 Body 的工具，转动部件无法分开 | `ir_patch` 新增 `add_body` / `update_body` |
| 声明支持 `body_id`，实际拒绝并误赋给 Feature | 创建操作消费该路由字段，不写入特征属性 |
| Face 附件草图误导模型使用局部坐标 | 明确所有轮廓输入都是面上的世界 x/y/z |
| 逐齿叠加实体触发 60 秒编译超时 | 工具说明推荐一次闭合轮廓 + pad |
| 装配被默认“总共一个实体”拒绝 | 多 Body 按独立内核测量验证每件恰好一个实体 |
| STEP 缝合后边数变化导致误报 | 多件装配仅在面数、体积、面积、包围盒、有效性和实体数均一致时接受边数变化，并在报告中记录 |
| 不能定义传动或观察指定角度 | Body 声明 `motion`，`geo_view.driver_angle_deg` 和网页转角滑块 |
| 不能便捷创建锥形削笔通道 | 支持可定位的 `additive_cone` / `subtractive_cone`，真实内核测量验证 |

## 复现

```sh
.venv/bin/python tools/agent_driver.py --new \
  --model-id sharpener_trial --data-dir .tcad_sharpener \
  --requirement '创建一个削铅笔的工具盒，支持摇杆转动从而实现削铅笔。' \
  --calls tools/sessions/pencil_sharpener.json
```

样例有四个独立零件：集屑盒、驱动轴/摇柄/齿轮、从动齿轮/刀架、刀片。
包含两轴支承、固定导向套、锥形通道、排屑窗和倒角刃口。24 个特征中一个旧直孔被抑制。
盒体 120×90×70 mm，壁厚 3 mm、底厚 4 mm；这些是设计假定，不是用户确认尺寸。

转动声明如下；从动刀架和刀片的 ratio 是 `-16/22`，固定盒体的 motion 为 null：

```json
{"motion":{"pivot":{"x":28,"y":0,"z":38},"axis":{"x":0,"y":1,"z":0},"ratio":1}}
```

真实构建、STEP 回读、0°/90°/360°预览均通过。输入 90°时，从动件转 −65.4545°；
输入 360°时转 −261.8182°。角度预览不改变 IR、静态导出或 Gate 结论。
运动图片保存在 `vN/motion_90/` 等独立目录，默认零角度图片保留在 `vN/`。

## 验收范围

当前是**可转动的机构概念草稿**。齿轮采用近似轮廓，运动按预设比例驱动，
没有齿面接触、碰撞、切削受力或材料去除求解。夹紧送料、轴承/紧固细节、
实际削尖效果仍需完善和实物试验。构建通过不能证明完整削笔功能。

手动 driver 会执行工具与 Gate，但不执行引擎的最终 `design_review` 状态转换；
因此样例复核明确保留待验事项，不能将工具收到复核称为功能验收通过。

## 第二轮：机械细化与调用链优化

新增 `tools/sessions/pencil_sharpener_efficient.json` 可通过同一个 driver 复现。
改用模数 2 mm 的 18/20 齿组合，中心距 38 mm、从动比 −0.9，
增加两个独立可更换轴套和导向套上的名义夹笔压杆/旋钮。
送料方式是松开压杆后人工推进；压杆没有真实螺纹，未求解夹紧力。

新增工具：

- `ir_gear_profile`：用齿数、模数、压力角、齿厚减量、相位和采样数生成
  完全约束草图。齿面按渐开线采样，齿根为径向过渡，拒绝标准无变位齿轮
  的根切风险参数；不是精确曲线或制造认证。
- `geo_check_motion`：一次构建，复制真实 BRep 并按声明轴/比例旋转，
  测量指定零件对在多个输入角度的交集体积。输出角度、零件 ID、干涉体积
  和阈值。默认检查所有零件对；安装件可指定实际要检查的配合对。
  `sampled_clear` 只覆盖所选角度/零件对，不证明连续运动、接触力或切削。
- `ir_get(ids=["drive_gear"])`：按 ID 读取精确状态；默认省略可重建默认值，
  `include_defaults=true` 可恢复完整字段。完整 IR 仍可无损解析。

编译器对纯 Block 约束批量提交，避免逐边触发求解。普通尺寸约束仍按原路径
处理。引擎提示按机构阶段批量 patch、优先 digest/按 ID 读取、只渲染必要视图。
修正 `ir_commit` 原先 30 秒外层超时早于内核 120 秒超时的问题；外层预算
为 480 秒，内核每项调用仍有限时，用户停止机制保留。

实测最终 7 个 Body 均为一个有效实体，完全约束草图与 STEP 回读通过。
在 0/10/20/30/45/60/90/180/270/360 度检查 9 对零件，未发现超过
1e−6 mm³ 的干涉；刀片与安装座的预期安装交叠不纳入这些配合对。
同一四件机构在本机的采样检查由约 15 秒降至约 6 秒，性能数字只代表这次实测。

样例工具参数的紧凑 JSON 文本从 35,899 字符降至 12,703 字符（约 65%），
包含新增轴套、夹笔件及采样检查；这是字符量，不是实际供应商 token 计费。
验证：1341 项 Python 单元/内核测试、29 项前端测试通过，最终增量回归 40 项通过。

参数公式参考 [KHK 齿轮尺寸计算](https://khkgears.net/gear-knowledge/gear-technical-reference/calculation-gear-dimensions/)。
连续碰撞、真实齿根曲线、螺纹/送料运动、切削受力与材料去除仍未实现；
保持概念草稿状态，不以构建和采样通过代替实际削笔验收。
