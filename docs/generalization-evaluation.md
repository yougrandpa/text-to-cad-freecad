# 提示冻结与独立评测

全局提示只保留工具协议、需求来源、编辑身份和完成证据要求。通用几何工具保持可用；
支架及重力悬挂等专用流程通过 `ir_help(topic="workflow")` 发现，再按名称获取。
只有选中的流程会在本轮后续请求中提供对应工具，下一轮重新发现。
原生草图、特征与装配仍通过各自主题获取契约，不因紧凑工具的形状范围而受限。

`review/generalization/cases.json` 保存三个独立任务和一个直升机诊断任务。
这些任务没有用于本轮提示改写，输入只包含用户需求，不提供建模步骤。
这里的“独立”指未参与本项目本轮开发，不能证明它们未出现在模型训练数据中。
直升机单独记录，不计入独立任务通过率。题量小，结果仅用于定位能力边界。

冻结后再调用模型：

```sh
.venv/bin/python tools/evaluate_generalization.py --freeze
.venv/bin/python tools/evaluate_generalization.py --check
.venv/bin/python tools/evaluate_generalization.py --run
```

冻结文件记录实际全局提示，以及完整工具表、初始工具表、帮助内容、流程规则、
发现逻辑、评测器代码和题目哈希。步数与时间限制一并冻结。
每题开始前检查一致性，变化则中止；基线文件不能覆盖，修改后必须创建新版本。
禁止看完结果后修改同一基线的提示或题目再合并成绩。

真实运行需要明确授权，使用当前保存配置，每题新建隔离数据目录和会话。
批次内固定同一份服务设置；报告只保存模型、参数和端点哈希，不保存凭据。
独立验收条件不会进入模型输入。结果保存在忽略的 `.tcad_eval/` 中，
包含事件记录、IR、产物、每题摘要及批次报告。

自动检查包括交付路径、产物版本与最终 IR 一致、几何有效性及题目要求的实体数、
体积或运动证据。体积相同不能证明外形相同，存在关节和帧也不能证明运动正确。
因此自动检查通过仍需对照原始需求检查外形、连接和运动，报告的
`task_verified` 默认为 false。模型自述完成、Gate 通过和导出成功不能替代任务验收。

每次运行应记录失败原因及人工检查结论。能力改进使用新版本并补充新的独立任务，
不把本次诊断答案写回全局提示。
