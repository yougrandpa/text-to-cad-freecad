# 构建检查与功能验收

构建通过后不能自动认定完整任务已完成。例如“削铅笔工具箱”的实心底座可以
通过 BRep、STEP 往返和导出检查，但这些检查不证明有腔体、入口、刀片或切削能力。

生产配置默认 `loop.require_design_review: true`：

1. 引擎将用户原话写入 IR 的 `requirements.raw_text`，追加后续要求；旧会话缺少
   原话时从用户消息回填。模型不能覆盖这段文字。该元数据更新会产生一个新 IR 版本。
2. 模型先列出功能和特征计划，再分步修改 IR、构建。`ir_commit` 通过是检查点，
   不会自动结束回合，模型应继续完成尚未建出的特征。
3. 最后构建后单独调用 `design_review`，包含 `summary / checklist / remaining_work`。
   每个 checklist 项用 `source_text` 引用用户原话，用 `check_ids` 引用当前 Gate 的证据。
4. 引擎检查证据属于当前版本、检查实际通过、为确定性阻断检查，且关联到已确认的
   用户约束。通用实体合法性/导出检查、结构性特征计数、跳过项和近似提示不能当成功能证据。
5. 没有证据或有剩余工作时，返回 `state: draft` 和完整 `completion_review`。
   构建产物仍可预览、下载和继续修改。模型若在构建后持续只输出文字而不复核，
   停滞检测也会以待验收草稿结束。通过时 `scope` 为 `recorded_constraints`，
   界面只显示“已记录的需求约束验收通过”。

模型自行设置 `confirmed=true` 不能独立证明用户确认过某个尺寸。复核要求数值能在
`source_text` 中找到；计算得到的体积、默认尺寸、含糊的中文数量或语义推断仍可能
保持待验收。`count` 只测实体数，不能用“一个工具箱”推断削铅笔功能。该规则保守，
尚不支持单位换算、任意中文数字或数值推导的自动溯源。

`completion_review.verified` 验证的是该次复核所引用的**已记录约束**，不是整个产品
的自然语言语义。清单由模型解释，系统目前没有完备的自动需求覆盖证明；模型可能漏项，
因此用户仍应核对清单。CAD 几何不能替代真实切削效果、装配间隙、强度或安全性能试验。
无法测量的功能应在 `remaining_work` 中保留，不应编造通过证据。

旧接口 `/models/{id}/verdict` 的 `verified` 仍表示当前版本的构建与发布验证，
不代表功能验收。旧历史报告不会被自动升级为功能完成。

为兼容直接嵌入的几何测试流程，内部 `tcad.loop.engine.LoopConfig` 默认保持几何模式；
`build_services` 根据 YAML 默认启用复核。显式设置 YAML 为 false 会恢复构建即终止，
界面仍只显示构建通过，不能据此声称完整功能已验收。

本轮全量验证：1278 项 Python 测试通过（88.49 秒），21 项 Node 前端测试通过。
随后新增“模型不提交复核”的草稿回退测试，与引擎测试一起运行 45 项通过。
随后静态资源缓存与页面调整的定向 Python 测试 80 项通过，Node 测试仍为 21 项通过。
实际浏览器已验证 WebGL 网格加载及视角切换，修复共享着色器变量精度不一致造成的
静态图片回退。未执行实物切削验收。

回归覆盖：第一次通过后继续创建腔体、真实内核体积变化、未测量功能返回草稿、
来源/数值不匹配拒绝验收、遗漏已确认约束、旧 Gate 失效、原始需求保护与历史回填，
以及前端终态文案。脚本与实时供应商测试分别验证编排和真实模型行为。
