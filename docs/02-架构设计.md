## 1. 需求规格

| 维度 | 内容 | 状态 |
|---|---|---|
| 目标与用途 | 让**不会 CAD 的人**用对话拿到可继续编辑的参数化模型 + 可导出的 STEP/STL。FreeCAD 全量源码作为几何内核与 Python API 引擎，**不改内核**，只用 `Part` / `PartDesign` / `Sketcher` | 默认假设 |
| 成功标准 | ① 典型零件（支架/法兰/轴类，≤8 特征）一次生成通过几何 Gate ≥70%；② 发话→可导出 STEP 的 P95 ≤ 90s；③ 单模型平均 token ≤ ¥2；④ 「改一处尺寸」不破坏其它已确认特征 ≥95%；⑤ STEP 往返体积误差 <1e-6 | 默认假设 |
| 任务结构 | ① 从零建简单机械零件 60%；② 在已有模型上改特征/尺寸 30%；③ 导入已有 STEP/DXF 做修改或测量 10% | 默认假设 |
| 数据/资源边界 | FreeCAD 源码（26.3.0dev）作几何引擎；输入资产：用户上传 STEP/IGES/STL/DXF；可选公司标准件库 | 默认假设 |
| 硬约束 | ① headless 可跑（无 GUI）为**第一硬约束**；② 支持完全离线/私有化部署；③ 遵守 FreeCAD LGPL-2.1，静态链接闭源不做、改动回馈；④ 先单机多进程，不做分布式 | 默认假设 |
| 用户与场景 | 单用户本地桌面为主（CLI + 轻量 Web）；「一个项目 = 一个模型」，支持同模型多会话续聊 | 默认假设 |
| 边界（不做什么） | **明确不做**：GUI 交互式建模 / 自由曲面与外观造型 / 装配约束求解与运动仿真 / 工程图 2D 出图 / 仿真与 CAM 与切片 / 多用户实时协作 | 默认假设 |
| 技术栈约束 | Python 3.11（对齐 FreeCAD 内置解释器）、pydantic v2、asyncio、FastAPI | 默认假设 |

### 1.1 五个十字路口的定稿

| 分叉 | 定稿 | 一句话理由 |
|---|---|---|
| A 形态 | **混合，先内核后协议**：先做自有 harness 内核（C/V/S/L 自有），预留 MCP 协议面把工具层暴露给外部客户端 | 差异化全在 C/V/S；但「可被嵌入」是后期增量 |
| B 生成路径 | **B3**：声明式特征树（IR）为主路径，`raw_python` 作**默认禁用、三重门放行**的逃生舱 | 纯自由脚本会让 V 层形同虚设——黑盒脚本跑完只剩一个 BRep，无法做特征级校验 |
| C 真相源 | **C3**：自有中间表示 IR（特征 DAG + 参数 + 稳定命名）为唯一语义真相；FreeCAD document 只是投影产物 | 一并解决「把那个孔往右挪 5mm」的指代消解与上下文爆炸 |
| D 视觉反馈 | **上**，但改为「worker 回传网格 + supervisor 侧软件光栅化」（原因见 §12-1：FreeCAD 渲染在 Gui 层，无头用不了） | 从「闭眼画图」到「睁眼画图」，是本项目最大架构增量 |
| E 参数化 | **E2**：增量改 IR 节点 + 重放 | 这是「聊天式 CAD」与「一次性生成器」的分界线 |

## 2. 架构范式 P

| 子维度 | 决策 | 理由 |
|---|---|---|
| 扩展方式 | **插件化（内核无特权）** | 工具、校验器、渲染器、编译器后端全部经注册表注入，内核不认识任何具体能力。CAD 能力边界会持续长（今天 Pad/Pocket，明天 Loft/SheetMetal），内核不能硬编码。模式来源：`dependency-injection`（内核极薄，能力靠注入，可逆注册） |
| 配置方式 | **声明式为主 + 命令式为辅** | YAML 描述工具白名单/审批策略/预算/校验规则集/模型配置；命令式仅限默认禁用的逃生舱脚本。模式来源：`declarative-configuration` |
| 部署拓扑 | **单机多进程**（supervisor + worker 池），接口按 actor 设计以预留远程 worker | FreeCAD 是全局状态极重的 C++/OCC 库，一次段错误不能带走整个会话；池化还能并行跑多方案。模式来源：`actor-model`（隔离实体间消息传递） |
| 编排模式 | **中心化 supervisor** | 聊天式交互天然是单线程线性会话，去中心化在这里只增加复杂度不增加能力 |

> 补充说明：这四个子维度是参考样例，非完备。本项目真正有区分度的 P 决策是**「几何内核与语义真相的分离」**——模型永远不直接读写 FreeCAD document，只改 IR；FreeCAD 被降级为一个「编译器后端」。这条决定了 T/S/V 三层的全部形态。

## 3. 技术栈选型

| 项 | 选型 | 理由 |
|---|---|---|
| 语言 | Python **3.11** | 与 FreeCAD 内置解释器版本对齐，避免 ABI 与 `sys.path` 冲突 |
| CAD 运行时 | 本仓库源码构建的 FreeCAD **26.3.0dev** → `build/debug/bin/FreeCADCmd` | 版本锁定、可复现；构建命令见 §3.1 |
| 编排框架 | **不用框架**：`asyncio` + 自写 agent loop | Harness ≠ 库。引入 LangChain/LangGraph 会把 E 层让渡给别人，与分叉 A 的定稿矛盾 |
| 数据建模 | `pydantic>=2.7` | 「类型完整」门槛靠它兜住；配置/IR/工具 schema/校验结果全部用它 |
| LLM 接入 | `openai>=1.40`（OpenAI 兼容接口，可指向 vLLM / Ollama） | 满足离线/私有化硬约束 |
| 服务与前端 | `fastapi` + `uvicorn` + SSE | 聊天流式输出 + 审批中断推送 |
| 会话存储 | SQLite（WAL 模式）+ 文件系统 | 见 §4.4 |
| 图像处理 | `numpy` + `Pillow`（**仅在 supervisor 侧**，不进 FreeCAD 进程） | 无头软件光栅化渲染器 |
| PNG 编码 | 双后端：`Pillow` 可用则用，否则**纯 stdlib `zlib`+`struct` 手写 PNG** | FreeCAD 内置解释器不保证有 Pillow；纯 stdlib 后端保证渲染永不因依赖缺失而挂 |
| 进程间协议 | JSON Lines over stdin/stdout（请求/响应带 `id` 关联） | 简单、可调试、无额外依赖；不跨进程传 BRep |
| 可观测性 | 结构化 JSONL 事件日志（§4.4 events） | 与 S 层共用一份真相，不另起一套 |

### 3.2 Worker 启动方式（已核实）

CLI 选项在 `src/App/Application.cpp:2424` 起注册，其中：
- `-c, --console` → `Application.cpp:2433`，置 `Console=1` / `RunMode=Cmd`
- `-M, --module-path` → `:2454`；`-P, --python-path` → `:2456`
- `input-file`（位置参数）→ `:2468`，由 `Application::processFiles()`（`:3092`）经 `Base::Interpreter().runFile(...)`（`:3119`）执行

因此 worker 启动命令为：

```bash
"$TCAD_FREECAD_PREFIX/bin/FreeCADCmd" \
  --console \
  -P "$(pwd)" \
  "$(pwd)/tcad/worker/bootstrap.py" \
  --worker-id=w0
```

`bootstrap.py` 由 `runFile` 执行后进入阻塞式 stdin/stdout RPC 循环，进程因此常驻。

## 4. 六层设计

### 4.1 E 执行循环

**三原语**（借鉴 `Codex Harness` 的 Thread ⊃ Turn ⊃ Item，本设计映射为 Thread ⊃ Turn ⊃ Step）：

| 原语 | 定义 | 终止 |
|---|---|---|
| `Thread` | 一个模型的一条对话线 | 用户关闭 / `session_end` |
| `Turn` | 一次用户发话 → 直到 Gate 全绿、需人工介入或熔断 | 见下方终止条件 |
| `Step` | 一次 LLM 调用 + 其触发的全部工具执行 | 单次工具链完成或超时 |

**设计决策**

1. **执行模式（策略库）**：
   - `M1 循环直到完成`（主路径）：Step 循环 → 改 IR → 编译 → Gate → 未全绿则把 Gate 报告回灌继续
   - `M2 分叉与综合`（可选，用于「我不确定你要哪种」）：并行生成 N=3 个候选 IR，各自编译校验，按 Gate 通过项数与告警数打分选优
   - `M3 对抗性验证`：独立 critic step（隔离上下文，只读产物 + 需求规格），专门挑错，输出 `advisory` 级发现
2. **终止条件必须确定性**（防循环论证）：

| 类型 | 条件 | 状态 |
|---|---|---|
| 成功 | `GateReport.passed == True` | `SUCCEEDED` — **唯一「完成」定义** |
| 人工 | 用户显式确认 / 拒绝 | `CONFIRMED` / `ABORTED` |
| 熔断 | 任一项上限被越过：`steps > max_steps_per_turn` ∨ `tokens > max_tokens_per_turn` ∨ `step_elapsed > step_timeout_s` ∨ `turn_elapsed > turn_wall_clock_s`。**任何一项为 `null` 即该项不设上限，且不参与熔断**（见 §4.1 第 3 条） | `EXHAUSTED`（**不是成功**） |
| 不可恢复 | 连续编译失败 > `max_compile_retries`（`null` = 不设上限） | `FAILED` |
| 待人工 | 工具返回 `ask` 且未获批 | `AWAITING_APPROVAL` |

   **模型说「我完成了」不构成终止条件。** 模型唯一能做的「声称完成」动作是调用 `ir_commit`，之后由 Gate 独立判定。
3. **保险是可选的，且默认不设上限**。轮数、token、每 Step 与整 Turn 双超时、编译重试，全部在 `loop/budget.py` 集中实现，不允许分散在业务代码里；每一项都是 `int | None` / `float | None`，**`None` = 该项不设上限**（用 `None` 而非 `0`/大数：`0` 的语义歧义会静默改变行为，`None` 不会）。

   默认全部为 `None` —— **本 harness 不对一个 Turn 施加工作量配额**。此时一个 Turn 只会因三件事结束：Gate 全绿、`FAILED`、`AWAITING_APPROVAL`。

   需要上界时用 `configs/policies/strict.yaml`（该 overlay 把五项**全部**限住；漏掉任一项都会留下一处无上限）。

   **区分「工作量上限」与「单次请求活性」**：去掉前者不改变后者，也不应改变。一次挂死的模型调用仍会撞上传输层超时（`llm.request_timeout_s`）；一次挂死的工具调用仍会撞上 `ToolSpec.timeout_s`；死掉的 worker 仍会撞上 worker 传输超时。前者是策略选择，后者是防卡死。
4. **无上限状态必须可见**：`GET /health` 报告 `budget.{limits,unbounded,unbounded_all}`，界面在顶栏显示「无预算上限」徽标。理由是实测教训——一个静默的宽松设置会让人用「跑了很久没结束」来推断它，而那不是界面该有的行为。
5. **客户端断开必须终止 Turn**（无上限之前靠 `max_steps_per_turn` 兜底，之后不会自己停）：`/chat` 的 SSE 生成器在 `finally` 里取消 Turn 任务。注意 `start` 帧必须位于 `try` **之内**——生成器在进入 `try` 之前被关闭时 `finally` 不会执行，任务就会泄漏。
6. **失败处理**：编译失败不抛给模型裸 traceback，而是先由 `worker/introspect.py` 定位到**具体特征 id**，转成结构化错误（`feature_id` + `error_kind` + 相关测量），再回灌。这是「模型能自己修」的前提。

**落地规格**

```python
# tcad/loop/engine.py
class LoopEngine:
    def __init__(self, deps: Deps, strategy: Strategy): ...
    async def run_turn(self, thread: Thread, user_msg: Message) -> TurnResult:
        """完整 Turn 生命周期：pre_turn → (pre_step → LLM → tools → pre/post)循环
        → pre_commit → Gate → on_gate_result → post_turn"""
    async def _run_step(self, ctx: TurnContext) -> StepResult: ...
```

| 类 | 职责 | 失败处理 |
|---|---|---|
| `LoopEngine` | Turn 主循环、状态机推进 | 任何异常 → `TurnResult(status=FAILED, error=...)`，事件日志留痕 |
| `Strategy`（M1/M2/M3） | 决定 Step 序列形态 | 策略内部异常不外溢，降级为 M1 |
| `Budget` | 轮数/token/时间三重计数与判定 | 触顶抛 `BudgetExhausted`，由 engine 转 `EXHAUSTED` |
| `CommitPipeline` | `ir_commit` → 编译 → Gate → 回灌 | 编译失败转为结构化错误，不终止 Turn |

### 4.2 T 工具注册

**设计决策**

1. **统一 `ToolSpec` + 三档权限**，权限是**结构性的**（内核判定），不是提示词约束：

| 档 | 工具 | 策略 |
|---|---|---|
| `read` | `ir_get`, `ir_list_features`, `ir_digest`, `geo_view`, `geo_measure`, `asset_export`, `asset_import` | 免审批；`concurrency_safe=True` 可并发 |
| `write` | `ir_patch`（增删改 sketch/feature/参数/约束）, `ir_commit` | 先过 IR schema + 语义预检；写前自动快照；失败不消耗审批 |
| `privileged` | `raw_python`, `fs_write_outside_workspace`, `net_fetch` | **默认 disabled**；放行需三重同时满足，见 §4.5 |

2. **按需筛选子集**（借鉴 `Codex Harness` 的动态工具加载，避免 prompt 膨胀）：按 `Turn.kind` 注入——
   - `kind=inspect` → 只注入 `read` 档（不暴露写工具，物理上防误写）
   - `kind=create` → `read` + `write`
   - `kind=modify` → `read` + `write` + `ir_get` 强化
   - 仅当 `turn.privileged_requested` 且策略允许 → 追加 `privileged`
3. **模型不直接操作 FreeCAD document**：`geo_*` 工具全部只读，且只读**产物副本**（见 §4.6 CQRS）。所有写操作只经过 `ir_patch`。

**落地规格**

```python
# tcad/tools/base.py

```

### 4.3 C 上下文管理

**设计决策**

1. **窗口假设 128k tokens**（待标定，见 §12-6）。预算表：

| 区块 | 预算 | 生成方式 | 更新时机 |
|---|---|---|---|
| 系统提示 + IR schema + 工具说明 | 6k | 静态前缀，走 prompt cache | 版本变更时 |
| 当前状态摘要（`GeometryDigest`） | 2k | **程序生成，非模型总结** | 每次 IR 变更后 |
| 最近一次 Gate 报告（仅失败项 + 偏差数值） | 2k | 程序生成 | Gate 后 |
| 视图截图 | 2.4k（3×0.8k） | 光栅化渲染 | **仅 `visual_checkpoints`**：首建 / 大改 / 收尾 |
| 对话历史 | 余量 | 滚动窗口 + 超阈值摘要 | 每 Step |

2. **三档降级**：`used/limit < 0.70` → `full`；`< 0.85` → `summarized`（近 6 轮原文 + 更早摘要）；`≥ 0.85` → `minimal`（仅系统前缀 + `GeometryDigest` + 当前轮）。
3. **几何摘要投影（`GeometryDigest`）是本层核心，也是本项目最关键的原创设计**：
   - 明确要做：特征树（顺序+类型+参数）、拓扑计数、`optimalBoundingBox()` 尺寸、`Volume`/`Area`、IR 直读的孔位孔径、Gate 偏差 diff
   - 明确不做：**绝不把 BRep 顶点流塞进上下文**；**不让模型「读」几何**
   - 复用约束：digest 的测量值必须与 V 层 Gate 复用**同一个 measurement 层**（`worker/introspect.py`），否则两处真相互相打脸
4. **截图预算的硬约束**：多模态 token 极贵，绝不允许每步渲染。`visual_checkpoints` 由 E 层显式声明，C 层只被动消费。

**落地规格**

```python
# tcad/context/assembler.py
class ContextAssembler:
    def build(self, ctx: TurnContext, *, images: list[ImageRef]) -> list[Message]: ...
    def _level(self, used: int, limit: int) -> Literal["full","summarized","minimal"]: ...

# tcad/context/digest.py
class GeometryDigest(BaseModel):
    model_id: str
    ir_version: int
    bodies: list[dict]              # [{name, feature_chain:[{name,op,params}]}]
    topology: dict                  # {solids, faces, edges, vertexes}
    bbox: dict                      # {x,y,z}  ← 来自 optimalBoundingBox()，不是 BoundBox
    volume: float
    area: float
    key_dimensions: dict            # 从 IR 直读，不从 BRep 反推
    spec_deviation: dict            # 与 RequirementSpec 的偏差
    text: str                       # 渲染成 ≤2000 token 的文本块
```

**失败处理**：worker 不可达 → digest 降级为「IR 结构摘要（无几何测量）」并在文本里显式标注 `[未验证几何]`，让模型知道自己在盲区，而不是误以为几何已确认。

### 4.4 S 状态存储

**设计决策**（真相源分层，从下到上）：

| 层 | 内容 | 位置 | 性质 |
|---|---|---|---|
| L1 语义真相 | `IrDocument` | `data/models/<model_id>/v<int>.json` | 每次 commit 一个**不可变**版本 |
| L2 事件流 | `IrEvent`（append-only） | `data/models/<model_id>/events.jsonl` | **单一真相源**，可重建任意版本、fork、回滚 |
| L3 索引/元数据 | threads / turns / steps / token_usage / approvals | `data/tcad.sqlite3`（WAL） | 可重建，可丢 |
| L4 产物 | `.FCStd` / `.step` / `.stl` / `views/*.png` / `gate.json` | `data/artifacts/<model_id>/v<int>/` | 由 L1 重放生成，可丢 |

**治理（关键）**：
- 模型**不能**直接写 L1/L2。写入口只有内核的 `ir_patch` / `ir_commit`：内核生成新版本 → 先追加事件 → 再原子写新版本文件 → 更新 index。模型绕过不了，因为它没有文件写权限（`fs_write_outside_workspace` 属 `privileged` 档且默认禁用）。
- **先写事件再写快照**：崩溃后可从事件流重建，最多丢一次未提交的 patch。
- **每次 commit 前自动快照上一版本** → 回滚是 O(1) 的文件切换，不是重放。
- **乐观并发**：`IrPatch.base_version != current_version` → 拒绝（`ToolError.kind="semantic"`）。防多轮/多方案交错写坏。
- **并发写**：`model_id` 级互斥锁（同一模型同一时刻只有一个写入 Turn）；SQLite 单写者 + WAL。
- **阻塞隔离**：所有 FreeCAD worker 调用走 `asyncio.to_thread` 或进程池，绝不阻塞事件循环。

**核心事件类型**


### 4.5 L 生命周期钩子

**设计决策**

1. **拦截点**（9 个，均为真实可挂载的位置，不是概念）：

| 事件 | 挂在哪 | 典型用途 |
|---|---|---|
| `session_start` | 进程/会话建立后 | 载入策略、配额初始化 |
| `pre_turn` | Turn 开始前 | 配额检查、内容安全前置 |
| `pre_step` | 每次 LLM 调用前 | 上下文档位强制、成本上限 |
| `pre_tool_use` | 工具**执行前** | **主拦截点**：allow/ask/deny |
| `post_tool_use` | 工具返回后 | 审计、脱敏、异常上报 |
| `pre_commit` | `ir_commit` 落盘前 | 规格一致性硬校验 |
| `on_gate_result` | Gate 出报告后 | 通知、badcase 回流 |
| `post_turn` | Turn 结束后 | 指标埋点、成本核算 |
| `session_end` | 会话结束 | 清理、持久化 |

2. **两类 Hook**（借鉴 `Claude Code` 的「确定性拦截」产品化范式）：
   - `policy`：进程内 Python 函数，确定性执行，低上下文成本，可 `deny`
   - `command`：外部命令，stdin 喂 JSON、stdout 收 JSON，超时 5s，超时视为 `deny`（fail-closed）
3. **合并规则（确定性）**：任一 `DENY` → 整体 `DENY`；否则有 `ASK` → `ASK`；否则 `ALLOW`。
4. **审批协议**：`ask` → Turn 置 `AWAITING_APPROVAL`，写 `approvals` 表，同时 SSE 推 `approval_request`；客户端 `POST /approve {approval_id, granted}` 恢复。CLI 下走 stdin 提示。
5. **高危拦截必须纵深，不单点**（对应生产清单「高危拦截要纵深」）。`privileged` 工具放行需**三重同时满足**：
   - ① 静态配置 `policy.allow_privileged: true`（需人工改文件，模型改不到）
   - ② 存在未过期的 `ApprovalRecord`，且 `approval.tool_name == 本次调用`
   - ③ 子进程沙箱生效（`sandbox-exec` / `bwrap` + 只读 bind mount + 无网络 + 独立低权限用户）
   **任一缺失即 deny。不依赖模型分类器判断是否高危。** Hook 通道自身不可被 Agent 修改（配置在启动时冻结，运行期只读）。

**落地规格**

```python
# tcad/hooks/dispatcher.py
class HookEvent(str, Enum):
    SESSION_START="session_start"; PRE_TURN="pre_turn"; PRE_STEP="pre_step"

    POST_TURN="post_turn"; SESSION_END="session_end"

    ALLOW="allow"; ASK="ask"; DENY="deny"
```

**失败处理**：Hook 抛异常或超时 → `DENY` + 事件日志记录 `hook_failed`。**永不 fail-open。**

### 4.6 V 评估接口

**设计决策**

1. **校验器是插件，纯函数式**：`(CheckContext) -> CheckResult`。`CheckContext` 只含**只读产物**（IR 快照 + 导出文件路径 + worker 只读句柄），不含生成路径的内存对象。
2. **独立读路径（CQRS）**：Gate 不读 `LoopEngine` 手里的 `IrDocument` 对象，而是重新从磁盘加载 IR 快照 + 重新从磁盘读导出产物。**这是「不让生成方给自己判卷」的结构保证**，不是纪律要求。
3. **三级置信度**，明确区分：

| 置信度 | 含义 | 是否参与 blocking |
|---|---|---|
| `deterministic` | 由几何内核或文件往返客观判定 | ✅ 参与 |
| `approximate` | 算法近似（如壁厚偏置法） | ❌ 只给 advisory |
| `unverified` | 无法自动判定（工程合理性） | ❌ 只生成人工复核清单 |

4. **第一梯队校验器（全部 `deterministic`，全绿 = Gate 通过）**

| check_id | 手段（已核实 API） | 判据 |
|---|---|---|
| `solid_validity` | `shape.isValid()`（内部走 OCC `BRepCheck_Analyzer`） | 所有 Solid 均 `True` |
| `solid_count` | `len(shape.Solids)` | 单实体时为 1 |
| `bbox_spec` | `shape.optimalBoundingBox()` | 与规格比对，容差 ±0.05mm |
| `mass_spec` | `shape.Volume` | 与规格比对，容差 ±1% |
| `sketch_fully_constrained` | `sketch.FullyConstrained` + `sketch.DoF` | 全部 `True` 且 `DoF == 0` |
| `round_trip` | `shape.exportStep(f)` → `Part.Shape.read(f)` | 体积相对误差 < 1e-6 且 `Faces`/`Edges` 计数一致 |
| `exportability` | `exportStep` / `exportStl` | 均成功且文件非空 |
| `wall_thickness` | `shape.makeOffsetShape(-t, ...)` | 偏置后仍为有效实体（**`approximate` 级**） |

> ⚠️ **五个必须写进代码的坑**（**已由 `FreeCADCmd` 26.3.0devR48708 实测确认**，证据见附录 B）：
> - `TopoShape.check(runBopCheck=False)` 的 `.pyi` 声明 `-> bool`，实测**成功返回 `None`、失败抛 `ValueError`**。适配层必须 `try/except`，**不能写 `if shape.check():`**。
> - `TopoShape.tessellate()` 的 `.pyi` 声明 `()`（无参），实测**必须传 tolerance**：`shape.tessellate(0.5) -> (List[App.Vector], List[tuple[int,int,int]])`。`.pyi` 在这一点上是错的。
> - **`FreeCAD.App` 不存在**：`from FreeCAD import App` 抛 `ImportError`。正确写法是 `App = FreeCAD`（与 `Mod/PartDesign/TestPartDesignGui.py:113` 一致）。
> - `SketchObject.setDatum(idx, v)` 在**约束冲突 / 求解失败**时抛的也是 `ValueError: Invalid constraint index: N`——**错误信息与真实原因无关**（`SketchObjectPyImp.cpp:915-920` 把 `SolverError` 一并映射成这句话）。编译器必须把它归类为 `solver` 错误，**不要**据此判断索引越界。
> - `SketchObject.solve()` 返回 `SolveStatus` 整数，**不是 DOF**；DOF 必须读 `sketch.DoF`（只读 int 属性）。
>
> **另一条被实测修正的认知**：`TopoShape.BoundBox` **是存在的**（实测 `XLength/YLength/ZLength/XMin...` 全部可用），之前源树阅读结论有误。设计取舍：**轴对齐尺寸校验用 `BoundBox`**（它就是规格比对要的东西），**`optimalBoundingBox()` 只在需要最小包围盒时用**（它是可旋转的 OBB，与轴对齐规格比对会得到偏小的数）。

5. **第二梯队（半确定性，规格表达式驱动）**：把自然语言需求解析成**机器可校验的约束表达式** `ConstraintExpr`，由程序判定。溯源要求：`source_text` 必须是用户原文片段，由程序绑定，不让生成模型自由发挥。**未被用户确认的表达式（`confirmed=False`）不参与 blocking。**
6. **第三梯队（诚实标注未知区）**：外观比例、工程合理性（可加工性、工艺常识、装配可达性）。**明确不自动评分**，只输出 `advisory` + 人工复核清单。理由见生产清单「诚实边界」：客观部分能自动评，主观部分强行打分就是造假。

**落地规格**

```python
# tcad/verify/gate.py
class CheckStatus(str, Enum):
    PASS="pass"; FAIL="fail"; ERROR="error"; SKIP="skip"

    check_id: str
    status: CheckStatus
    severity: Literal["blocking", "advisory"]
    confidence: Literal["deterministic", "approximate", "unverified"]
    message: str
    measurements: dict[str, float | str | bool] = {}
    expected: dict[str, float] | None = None
    evidence: list[str] = []          # 产物文件路径
    feature_id: str | None = None     # 让模型知道改哪

    model_id: str

    advisory_findings: list[str]
```

**失败处理**：校验器自身抛异常 → `status=ERROR`、`severity` 继承其声明。`blocking` + `ERROR` 视为不通过（fail-closed）。`SKIP` 仅在依赖缺失时出现，且在报告里显式列出 `skipped_checks`，**不允许静默跳过**。

### 6.4 编译器（IR → FreeCAD）：真实 API 调用序列

这是全项目**最需要照抄准确**的一段。以下写法与 FreeCAD 自身测试套件一致（`src/Mod/PartDesign/PartDesignTests/TestPad.py:44-57`、`src/Mod/Sketcher/SketcherTests/TestSketcherSolver.py:176-215`）：

```python
# tcad/worker/compiler.py
import FreeCAD, Part, Sketcher
from FreeCAD import App, Base

class IrCompiler:
    def compile(self, ir: dict) -> dict:
        doc = FreeCAD.newDocument(ir["model_id"])
        for b in ir["bodies"]:
            body = doc.addObject("PartDesign::Body", b["name"])
            for s in b["sketches"]:
                self._create_sketch(doc, body, s)
            for f in b["features"]:
                self._apply_feature(doc, body, f)
        doc.recompute()
        return {"ok": True, "doc": doc}

    def _create_sketch(self, doc, body, s: dict):
        sk = doc.addObject("Sketcher::SketchObject", s["name"])
        # 附着：面（LCS 子特征）或原点基准面
        if s["plane"]["kind"] == "face":
            target = doc.getObject(s["plane"]["feature_id"])
            sk.AttachmentSupport = (target, [s["plane"]["sub"]])   # 如 (pad, ["Face3"])
        elif s["plane"]["kind"] == "datum_plane":
            sk.AttachmentSupport = (doc.getObject(s["plane"]["feature_id"]), [""])
        else:
            # XY/XZ/YZ → doc.XY_Plane / doc.XZ_Plane / doc.YZ_Plane
            # 或 Body 内部：body.Origin.OriginFeatures[3]=XY, [4]=XZ, [5]=YZ, [6]=原点
            sk.AttachmentSupport = (getattr(doc, f'{s["plane"]["plane"]}_Plane'), [""])
        sk.MapMode = "FlatFace"                    # 已核实的 MapMode 枚举字符串
        sk.MapReversed = s.get("reversed", False)
        if s.get("offset"):
            o = s["offset"]
            sk.AttachmentOffset = App.Placement(
                App.Vector(o["x"], o["y"], o["z"]), App.Rotation()
            )
        body.addObject(sk)

        # 几何
        for g in s["geometry"]:
            if g["kind"] == "line":
                p0, p1 = g["points"]
                sk.addGeometry(Part.LineSegment(
                    App.Vector(p0["x"], p0["y"], p0["z"]),
                    App.Vector(p1["x"], p1["y"], p1["z"]),
                ), g.get("construction", False))
            elif g["kind"] == "circle":
                c = g["points"][0]
                sk.addGeometry(Part.Circle(
                    App.Vector(c["x"], c["y"], c["z"]), App.Vector(0, 0, 1), g["radius"]
                ), g.get("construction", False))
            elif g["kind"] == "arc":
                c = g["points"][0]
                sk.addGeometry(Part.ArcOfCircle(
                    Part.Circle(App.Vector(c["x"], c["y"], c["z"]),
                                App.Vector(0, 0, 1), g["radius"]),
                    g["theta1"], g["theta2"],
                ), g.get("construction", False))

        # 约束（type 串来自 Constraint.h 的 type2str 表）
        for con in s["constraints"]:
            idx = sk.addConstraint(Sketcher.Constraint(con["type"], *con["refs"]))
            if con.get("value") is not None:
                sk.setDatum(idx, con["value"])

    def _apply_feature(self, doc, body, f: dict):
        p = f["params"]
        op = f["op"]
        if op in ("pad", "pocket"):
            feat = doc.addObject(f"PartDesign::{op.capitalize()}", f["name"])
            feat.Profile = doc.getObject(f["profile_sketch"])
            feat.Length = p.get("length", 10.0)
            feat.Type = p.get("type", "Length")   # Pad: Length/UpToLast/UpToFirst/UpToFace/UpToShape
            feat.Midplane = p.get("midplane", False)
            feat.Reversed = p.get("reversed", False)
            if p.get("up_to_face"):
                feat.UpToFace = (doc.getObject(p["up_to_face"]["feature_id"]),
                                 [p["up_to_face"]["sub"]])
            body.addObject(feat)
        elif op == "hole":
            feat = doc.addObject("PartDesign::Hole", f["name"])
            # 属性名以附录 A 结论为准，首次实现时用 introspection 打印 getTypeIdOfProperty 校验
            body.addObject(feat)
        elif op in ("fillet", "chamfer"):
            feat = doc.addObject(f"PartDesign::{op.capitalize()}", f["name"])
            edges = [(doc.getObject(e["feature_id"]), [e["sub"]]) for e in p["edges"]]
            feat.Base = (doc.getObject(p["base_feature"]), [e["sub"] for e in p["edges"]])
            body.addObject(feat)
```

> 说明：`op` 名称小写，映射到 `PartDesign::Pad` / `Pocket` / `Revolution` / `Groove` / `Fillet` / `Chamfer` / `Draft` / `Thickness` / `Mirrored` / `LinearPattern` / `CircularPattern` / `MultiTransform` / `Hole` / `Additive*` / `Subtractive*`。类型字符串与属性名均已核实，见附录 A。
> **不使用 `body.newObject()`**：与 FreeCAD 自身测试一致的做法是 `doc.addObject(...)` + `body.addObject(...)`。

## 9. 层间交叉检查

| 关系 | 说明 | 风险与对策 |
|---|---|---|
| **E → V** | E 的唯一「成功」终止条件来自 `GateReport.passed` | Gate 不可用（校验器全 SKIP）时 E 只能进 `EXHAUSTED`，**不得**退化为「模型自评成功」 |
| **V → S** | Gate 走独立读路径：重新从磁盘加载 IR 快照 + 重新读导出产物 | 杜绝「校验生成路径内存对象」导致的自证；`round_trip` 天然是写盘再读回 |
| **S → L** | 唯一写入口 `ir_patch`/`ir_commit` 被 `pre_commit` 拦截 | 模型无直接文件写权限；配置启动时冻结，运行期只读 |
| **C ↔ V** | `GeometryDigest` 与 Gate 复用**同一 measurement 层**（`worker/introspect.py`） | 若两处各写一套测量代码，会出现「摘要说 10mm、Gate 说 10.1mm」的自相矛盾 |
| **T → IR** | `write` 档工具先过 `ir/validate.py`，schema/引用不合法直接 `ToolError`，**不消耗审批** | 避免拿审批额度浪费在低级错误上 |
| **C ← E** | 截图只在 E 声明的 `visual_checkpoints` 渲染 | 防止「每步截图」把 token 预算烧穿 |
| **E ← L** | `pre_step` 可降低上下文档位以控成本 | Hook 只能收紧不能放宽（放宽需 `allow_privileged`） |
| **T → L** | `read` 档 `concurrency_safe=True` 可并发；`write` 档串行 | `ir_patch` 的 `base_version` 乐观并发兜底 |
| **C → E** | digest 生成失败时降级并显式标注 `[未验证几何]` | 防止模型在盲区里误以为几何已确认 |

### B-2 Sketcher 错误语义（重要）

`setDatum(idx, value)` 在下列**两类完全不同的原因**下抛的是**同一句话**：

```
ValueError: Invalid constraint index: 8
```

源码 `Mod/Sketcher/App/SketchObjectPyImp.cpp:915-920`：`SketchObject::setDatum` 返回 `SketchSolveStatus::SolverError` 时统一输出这句。
实测踩坑：`DistanceX(0, 1)` 加在**已被 `Coincident(0,1,-1,1)` 绑到原点**的点上 → 约束冲突 → 报「索引无效」。改用「先绑原点、再标注自由端点」的顺序后一切正常。

**结论**：编译器遇到该异常必须归为 `solver` 类错误并把完整约束栈回灌，**不得**据此判断索引越界。

### C-2 五个新缺陷

|---|---|---|---|---|
| 1 | **worker 信封把内层失败压平成成功**：`rpc.dispatch` 把"handler 没抛异常"当作调用成功，而 handler 的返回体里 `ok=false`（约束冲突、无实体可导出、无网格可细分）被外层 `ok=true` 掩盖 | 一个**编译失败**的模型，在 supervisor 看来是**编译成功**。模型最后只看到"无法证明"，永远不知道自己的草图约束冲突了——而这恰恰是最该告诉它的那句话 | `dispatch` 在 `result["ok"] is False` 时构造错误信封（新增 `_first_error()` 统一三种内层错误形状） | `test_worker_envelope_never_flattens_nested_failure`、`test_broken_sketch_is_reported_as_a_solver_error` |

### C-3 方法论结论（值得沿用的做法）

1. **「操作者即 LLM」是缺失的那一层验证**。单元测试证明各层自洽；端到端测试证明装配可用；但**只有亲自当一回模型**，才知道工具面是否可猜、失败信息是否足以自修复。
2. **错误信息必须能传到该去的地方**。worker 的 solver 错误一直写得很好（带 `feature_id`、带具体约束、带数值）——但被②①两层掩盖。**「诊断质量」和「诊断可达性」是两件事，后者更容易被漏掉，也更致命。**
3. **静默无效比报错危险**。缺陷 3 的表现是"成功"：`ok=true`、`errors=[]`、体积不变。凡是"特征没生效"这类，都应在编译期做**贡献校验**（V 层已用体积/拓扑抓住，但那是事后）；这条留作后续增强。
4. 建模这类任务的**有效反馈密度**很高：Gate 一次就把「缺槽」和「方向反了」都指了出来，且给了 measured / expected / 偏差量。
